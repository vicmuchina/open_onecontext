OpenContext + Law Enforcer Auto-Setup (Fallback for agents)

Goal
- Install OpenContext CLI, OpenCode plugin, skill, and law config even if install.sh fails.

Read first (project blueprint)
- PROJECT_BLUEPRINT.md
- HOOKS_AND_ENFORCEMENT.md
- AGENT_WORKFLOW.md

Assumptions
- Linux/macOS shell
- opencode already installed
- python3 + pip available

1) Clone and install CLI

git clone https://github.com/vicmuchina/open_onecontext.git ~/.local/share/opencontext
cd ~/.local/share/opencontext/opencontext
pip3 install --user -e .

2) Ensure PATH

export PATH="$HOME/.local/bin:$PATH"

3) Install plugin + skill (global)

mkdir -p ~/.config/opencode/plugins
mkdir -p ~/.config/opencode/skills/opencontext
cp ~/.local/share/opencontext/opencontext/opencontext/plugin/opencontext-reminder.js \
  ~/.config/opencode/plugins/opencontext-reminder.js
cp ~/.local/share/opencontext/opencontext/docs/SKILL.md \
  ~/.config/opencode/skills/opencontext/SKILL.md

4) Optional project-local install

cd /path/to/project
mkdir -p .opencode/plugins
mkdir -p .opencode/skills/opencontext
cp ~/.local/share/opencontext/opencontext/opencontext/plugin/opencontext-reminder.js \
  .opencode/plugins/opencontext-reminder.js
cp ~/.local/share/opencontext/opencontext/docs/SKILL.md \
  .opencode/skills/opencontext/SKILL.md

5) Initialize GCC + law policy in project

cd /path/to/project
opencontext init --project-name "<name>" --goal "<goal>"
# or infer goal from an existing markdown spec:
opencontext init --project-name "<name>" --goal-file SPEC.md
opencontext law init
opencontext law validate
opencontext law guide

6) Configure model provider (OpenAI-compatible)

- First ask the user (do not guess):
  - provider base URL
  - API key env var name
  - project-local or global runtime target
  - whether to run benchmark auto-config now

- Edit .GCC/law-enforcer.json -> critic section:
  - baseUrl: provider base URL (example: https://llm.chutes.ai/v1)
  - endpointPath: /chat/completions
  - model: provider model id
  - modelFallbacks: optional ordered fallback model ids
  - apiKeyEnv: env var name holding API key
  - strictJsonRetryAttempts: retries malformed model output in stricter JSON-only mode (recommended: 1)
  - responseFormatStrategy: json_schema | json_object | json_schema_then_json_object
  - authHeader/apiKeyPrefix/headers: optional custom auth

- Export API key:
  export CHUTES_API_KEY="<key>"
  # or whichever env name matches critic.apiKeyEnv

- Or set once in runtime config files:
  - ~/.config/opencontext/law-runtime.json (global)
  - .GCC/law-runtime.json (project override)

- Auto-select best model + fallbacks and write runtime config:
  - Chutes:
    python3 ~/.local/share/opencontext/scripts/chutes_json_benchmark.py --base-url https://llm.chutes.ai/v1 --api-key-env CHUTES_API_KEY --response-format json_object --top 15 --write-runtime .GCC/law-runtime.json
  - Any OpenAI-compatible provider:
    python3 ~/.local/share/opencontext/scripts/chutes_json_benchmark.py --base-url https://<provider>/v1 --api-key-env <ENV_VAR> --max-models 20 --response-format json_object --top 15 --write-runtime .GCC/law-runtime.json

7) Customize behavior (no plugin edits)

- Edit `.GCC/law-policy.txt` for plain-language laws.
- Edit `.GCC/law-watchman-system.txt` to tune interruption strictness and confidence behavior.
- Edit `.GCC/law-failure-policy.txt` to tune actionable-failure vs noise judgment.
- Edit `.GCC/law-research-policy.txt` to tune when research must be checkpointed.
- Edit `.GCC/law-enforcer.json`:
  - `custom.rules` for trigger-based checks.
  - `custom.escalation` for soft vs hard enforcement.
  - `custom.hints` for preferred tools/skills/commands/MCP servers.
  - Model-only switches:
    - `gcc.failureClassifierRequireModelDecision`
    - `research.captureClassifierRequireModelDecision`
    - `watchman.requireModelDecision`
- Rebuild handbook:
  opencontext law guide

8) Runtime logs to inspect

- Plugin logs: run opencode with --print-logs --log-level DEBUG
- Law enforcer trace file: .GCC/law-enforcer-trace.jsonl
- Formatted watchman request/response:
  - opencontext io
  - opencontext law watch -n 20
- JSON model benchmark (Chutes or any OpenAI-compatible provider):
  - CHUTES_API_KEY="<key>" python3 ~/.local/share/opencontext/scripts/chutes_json_benchmark.py --base-url https://llm.chutes.ai/v1 --api-key-env CHUTES_API_KEY --response-format json_object --top 20 --write-runtime .GCC/law-runtime.json

If any test fails
- Re-copy plugin from source to ~/.config/opencode/plugins/opencontext-reminder.js
- Re-run opencontext law validate
- Restart opencode serve / opencode session
